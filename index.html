How I run an experiment

The checks I apply before I let a result influence what ships.

Frame the decision first

Write down what we will do if the test wins, loses, or is flat. One primary metric, named guardrails, and a minimum effect worth acting on.

Size it before launch

Compute the sample needed for the effect that matters, so a test is never stopped early because it "looks good". Try it in the lab above.

Check the plumbing

Sample ratio mismatch, logging gaps, novelty effects, and unit-of-randomization problems get checked before anyone reads the lift.

Control the error rate

No peeking without a sequential method. Correct for multiple metrics and segments. Variance reduction such as CUPED when pre-period data exists.

Report the range, not the point

Lead with the confidence interval and business impact, then the risks and limitations. Stakeholders get a recommendation, not a p-value.

Make it repeatable

Analysis lives in versioned code and pipelines with data quality checks, so the next test takes hours instead of weeks.
